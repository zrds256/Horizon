### [Brotli 解码器高危漏洞波及 Python 与 Node.js HTTP 组件](https://www.aikido.dev/blog/python-packages-vulnerable-node2shell-brotli-cve-2026-111497) ⭐️ 8.0/10

谷歌 Brotli 解码器高危漏洞 CVE-2026-111497（CVSS 4.0 评分 9.2）影响 1.0.3 至 1.2.0 版本，并波及 Python brotli/brotlicffi 与 Node.js HTTP 组件。远程未认证攻击者可发送特制压缩流，造成内存损坏、敏感数据泄露、进程崩溃，并可能执行任意代码；该漏洞最初以 Node2Shell 披露，后被称为 HTTP2Shell。Python 的 brotli 需升级至 1.2.1，brotlicffi 至 1.2.1.0；Node.js 修复版本为 22.23.4、24.22.1 或 26.12.1。OpenAI 表示于今年 2 月发现该问题，但这些细节来自单一厂商博客的转述，尚未在提供的材料中得到独立验证。

telegram · zaihuapd · 10月25日 02:42

**「背景」** Brotli 是 Google 开发的通用无损压缩算法，常用于 HTTP 内容压缩；其解码器需要处理来自网络的不可信压缩数据，因此解码阶段的缓冲区溢出会直接影响 Web 服务与 HTTP 组件。CVE-2026-111497 的溢出位于 Google Brotli 1.0.3 至 1.2.0 的 c/dec/decode.c，攻击者可通过特制 Brotli 压缩流触发相邻解码器状态内存损坏。Python 的 brotli/brotlicffi 和 Node.js 的 HTTP 组件因集成该解码器而进入受影响范围。

**「影响」** 使用受影响 Python Brotli 绑定或 Node.js HTTP 组件的服务端应优先升级，否则将暴露于无需认证的远程内存破坏风险。

### [Goose 编程语言：多数据栈与无共享并发](https://aardappel.github.io/goose/) ⭐️ 7.0/10

Hacker News 上出现了 Goose 编程语言的项目页面，作者 Aardappel 在讨论区表示该语言由他开发，并给出了 GitHub 仓库链接。讨论主要围绕其内存布局、多个数据栈以及无共享并发模型展开。一条被引用的设计说明称，Goose 的线程不共享内存，worker 被编译为拥有独立内存的独立程序，扁平值通过类型化队列以 memcpy 方式传递，因此语言中不存在数据竞争、锁、原子操作和内存序。评论者也提出疑问：多数据栈是否能直接在 C 中实现，固定数量的栈如何表示任意数量且动态大小的值（例如存放字符串的哈希表），以及 Rust 的某个子集能否通过类似约束获得相近的易用性。现有材料没有给出采用情况或性能数据，相关优势仍需验证。

hackernews · bobbydigitales · 10月24日 19:06 · [社区讨论](https://news.ycombinator.com/item?id=50224100)

**「背景」** Goose 是 Aardappel 开发的一种系统编程语言，其定位是内存安全，同时不依赖堆分配器、垃圾回收器或 Rust 式生命周期标注。它用多个数据栈组织动态数据，并采用“共享无关”的并发模型：工作线程各自拥有内存，只通过带类型的队列以 memcpy 方式传递扁平值。这与主流系统语言通常依靠垃圾回收、所有权与生命周期检查，以及共享内存加锁或原子操作来保证安全与并发的做法形成对照。

**「影响」** 对系统程序员和语言设计者来说，Goose 的当前价值更像一个可检验的设计样本：它用多数据栈和按值消息传递来回避生命周期与共享内存并发，但动态大小数据的表达能力和性能尚未由所给材料证实。

**「社区讨论」** 讨论尚未形成共识：有评论者追问多数据栈能否在 C 中复现，也有人担心固定数量的栈难以承载任意数量的动态大小值；另有评论将其与 Dart Isolates 类比，并追问 Rust 子集能否达到类似的易用性。

Apricitas 发布分析，审视美国媒体、电影和艺术行业约 20 万个岗位的流失，并评估人工智能在其中可能扮演的角色。该分析把 AI 影响与创意产业既有的经济压力放在一起讨论，而没有给出单一的因果结论；受数据限制，AI 究竟造成多少岗位减少仍不确定。相关话题在 Hacker News 引发大量讨论，涉及自动化、商业插画、流媒体商业模式和注意力经济等因素。对创意行业从业者和相关企业而言，这项分析凸显了在 AI 快速普及与行业成本收缩并行时，区分技术替代和其他结构性原因的难度。

hackernews · gnabgib · 10月24日 23:11 · [社区讨论](https://news.ycombinator.com/item?id=50226419)

**「背景」** Apricitas 是 Joseph Politano 撰写的宏观经济分析通讯，此次讨论围绕美国媒体、影视与艺术行业近年减少约 20 万个岗位展开。要判断其中多少由 AI 造成并不容易：媒体公司往往不愿公开其 AI 使用情况，既担心公众反弹，也要维护版权所需的法律基础。因此，这一议题更像是在评估多重行业压力与 AI 影响如何交织，而非给出可直接归因的单一结论。

**「对从业者的影响」** 对美国的媒体、影视与艺术行业从业者而言，这份分析的实际含义是：大约 20 万个岗位的流失不能简单归因于 AI，行业经济学，以及内容供给远超有限注意力的结构性变化，同样是关键因素。由于可核实的数据有限，AI 在这些失业中到底起了多大作用，仍是不确定的。

**「社区讨论」** Hacker News 评论大体认为创意行业岗位流失并非单一因素造成：有人赞赏文章没有强行判定 AI 是否为元凶，并指出娱乐业长期追求效率、将制作迁出洛杉矶等做法会带来连锁影响；也有人强调，早在 AI 出现前，内容供给已远超有限注意力和时间，流媒体涨价、订阅碎片化和用户体验恶化进一步压缩消费。具体到 AI，讨论者认为商业广告插画最可能已被自动化，且部分下降在 Stable Diffusion 兴起前后出现，但 Photoshop 智能工具等前 AI 技术也早有影响；同时有评论者提醒，仅凭现有数据很难分辨 AI 的实际作用，作者也将大部分岗位流失归因于其他因素。

### [gpu-unlock 项目解锁 RTX 3000 的 FP/BF16 指令发射率](https://github.com/Zagitta/gpu-unlock) ⭐️ 7.0/10

### [别把大科技公司当人看](https://seangoedecke.com/dont-anthropomorphize-big-tech-companies/) ⭐️ 6.0/10

rss · Sean Goedecke · 10月25日 00:00

**「背景」** 工程师很容易把大科技公司当成有情感、会讲公平的人，或反过来当成一套可逐条读懂的程序；Sean Goedecke 认为这两种模型都会误导人。

**「方案」** 他借用 Bryan Cantrill 提醒不要拟人化 Larry Ellison 的“割草机”说法，主张把公司看成一类危险但有用的机器，更像汽车而非朋友：它不尊重你的努力，也不会因你辛苦维护发动机就在刹车失灵时放过你。因此，公司里高影响工作往往难以预测，苦干数月的项目可能只换来一句“下一步呢”，十五分钟做出的小工具却可能获得赞赏；作者的建议是训练判断力，把大部分时间用于寻找低投入高回报的机会。对于“公司恨我”的说法，他认为这是危险的简写：经理可能确实记仇，但高管更常把员工当成有用或有缺陷的工具；而且经理通常只是暂时的，区分个人关系与公司机器有助于应对。作者同时警告不要矫枉过正，把公司当程序：公司由激励和不可读的人际关系驱动，手册、晋升指南和“最高优先级”只是庞大不可读依赖网络之上的可读外壳，照字面执行会困惑。

**「启示」** 公司不会像人一样记仇，却会像机器一样按激励淘汰人；理解这一点既意味着接受有时会无理由受罚，也意味着有机会用较小努力获得不成比例的回报。
